Moroccan Darija prompts with expected answers, and a runner that scores a model on them.

Most public Arabic evals are written in Standard Arabic. I wanted a small set of prompts in Darija, with the answers written down, that anyone can validate and re-run. The items are my drafts and have not been reviewed by a native speaker yet.

What works

  • works Schema validation of the JSONL file, with file, line and reason for every bad line
  • works Mock runs, with exact, normalized and fuzzy scoring, retries, a disk cache and resume
  • partial The OpenAI-compatible provider and the optional LLM judge exist, but CI does not call a live API
  • partial 150 items, all marked draft. Answers and fuzzy thresholds still need a native speaker
  • not done Results for a real model. There is no PyPI release either, so install from the repository

Quickstart

The mock provider needs no API key. Python 3.11 or newer.

git clone https://github.com/mohamedtaqysalmi/darija-eval-set
cd darija-eval-set
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
darija-eval validate
darija-eval run --no-resume

On Windows, activate with .venv\Scripts\activate.

How it works

run refuses to start if the dataset has an invalid line. Each prompt goes to the provider, the answer is scored by the method stored on the item, and the JSON file is rewritten after every new item so an interrupted run can resume. 

items.jsonl
   │
   ▼
validate ── bad line? ──► file:line: reason, run stops
   │
   ▼
provider: mock or OpenAI-compatible (retries, disk cache)
   │
   ▼
score: exact | normalized | fuzzy ── optional --judge on misses
   │
   ▼
results.json ──► this page

Scoring methods

Each item names its own method. The item counts are read from the results file above.

Method Passes when Items
exact The answer equals an expected answer character for character …
normalized The answers match after lowercasing, collapsing whitespace, dropping punctuation and diacritics, and unifying alef and ya variants …
fuzzy The difflib ratio against an expected answer reaches the item's threshold …

How I built it

Mock provider by default

CI and the Pages build never need a key. The cost is that the shipped leaderboard is a mock, which is why it is labelled as one.

difflib instead of a metric library

Fuzzy scoring is a string ratio after normalization. It misses paraphrases, but it adds no dependency and is easy to explain.

A fixed answer format for safety items

Safety prompts ask for one of two fixed phrases so they can be scored without a judge model. That tests instruction following as much as refusal.

A dataset card next to the data

DATASHEET.md says how the items were made and what review is still missing.

Limits and roadmap

  • Every item is a draft. Do not cite these scores as a measure of model quality.
  • Fuzzy scoring compares strings only.
  • Regional Darija variation and Arabizi-heavy chat are not covered well.

Next is the native-speaker review pass. To submit results for a real model, follow docs/submit-results.md. Open work is in the issues, and CONTRIBUTING.md explains how to propose items.
